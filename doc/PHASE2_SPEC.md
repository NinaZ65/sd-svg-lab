# Lab 2 项目规约

本规约依据 [Lab 1](requests/lab1/phase_cli_1.md) 与 [Lab 2](requests/lab2/phase_cli_2.md) 要求，经项目设计取舍确认后制定。Lab 1 的 `final` tag 对应现有行为与输出基线；本阶段不移动该 tag。Lab 2 的实现、测试、报告和证据完成后，在最终提交处建立 `p2` tag。

## 依赖与兼容边界

- 内核定义四个扩展点：`ShapeProvider`、`Command`、`TreeDecorator`、`AttributeHandler`，仅依赖接口及公开领域抽象，不导入插件实现或宿主装配代码。
- 插件只依赖内核公开 API；不同插件互不导入。宿主实例化插件，代码装配与配置装配共用注册、清单校验及失败回滚路径。
- 默认装配提供 Lab 1 的全部命令和六种图形。关闭本阶段可选插件时，CLI 输出以 `final` 的真实输出为逐字节回归基线；`final` 已有的无关行为不做隐式扩改。
- 读回失败保持原文档，重复 id 拒绝整个读入。这是完成 Lab 2 的 box 与插件契约所需的定向修正。

## 属性处理契约

- 多个处理器同时负责同一图形和属性时拒绝冲突，既不按偶然注册顺序覆盖，也不隐式组合。
- 处理器通过公开领域接口访问形状和必要子部件。属性事务记录局部修改；全部成功后才把一条 `set` 记为一个 undo 单元。若处理器在部分修改后抛错，逆序恢复已修改项，历史栈保持原样；不落到默认处理路径。
- 无处理器命中时沿用 Lab 1 白名单及错误输出。`box` 插件注册 `fill` 与 `label` 处理器，不扩大普通图形的属性集合。

## box 与 SVG 读回

- `box` 是带 `data-kind="box"` 的容器，必要子部件为 `<id>-rect` 与 `<id>-label`。创建前检查整棵新增子树的 id 冲突；冲突时不改变文档。
- 装有 box 插件时，读到缺少必要子部件或子部件类型错误的 box，拒绝整个 `read` 并保留原文档；未装插件时降级为普通 `g`。任何重复 id 都拒绝读入。
- 直接删除、移走或通过分组改变必要子部件归属的结构命令须拒绝；其他合法编辑仍可作用于子部件。`box` 自身可嵌套、整体移动和删除，不可 `ungroup`。

## 树标签与 dirty 语义

- `modified-star` 与最近一次成功保存的内容比较。`init`、`read` 建立干净基线；新建图形立即标 `*`；保存后清除；保存后再编辑并 undo 回保存点时，`*` 消失。
- 子节点内容或结构变化向其祖先及 SVG 根行传播。被删除节点不再显示，其原祖先按现存内容差异判断。
- 同一行先显示 `(box)`，最后显示 `*`。标签状态只存于对应实例字段；禁用全部标签时 `tree` 输出与 Lab 1 基线逐字节一致。

## dir 与 VSCode 扩展

- `dir` 使用目录访问接口与 Node 文件系统适配器；目录在前、文件在后，组内名称升序。符号链接及其他非目录项不跟随目标，显示为 `[FILE]`。不依赖文档，不修改目录、文档或历史。
- VSCode 扩展使用文件装饰提供者添加 `[]`，使用文档符号提供者生成原生 Outline。大纲解析保持独立 XML 边界；CLI 当前正则 SVG 解析器不直接复用。编辑中 XML 不完整可返回空大纲，扩展不得崩溃。

## 装配与错误

- 代码和配置装配使用相同的插件模块、选项、激活及注册校验流程。配置项按数组顺序处理，`enabled: false` 完全跳过，相对路径以配置文件目录解析。
- `contributes` 的四类名称集合与实际暂存注册逐项比较；同类同名重复拒绝。模块不存在、默认导出缺失、清单不一致、激活异常、配置无效按课程指定错误格式输出。单个插件失败只回滚本插件，后续插件继续加载。
- `stats`、`dir` 为独立命令插件，分别启用和禁用；`help` 由注册表提供的命令元数据生成。配置加载器不含具体插件名或类型分支。

## 验收口径

完成 Lab 2 要求的各过程节点和普通提交；每个插件独立可测；装配 A/B 对同一会话输出逐字节一致；无可选插件时对照 `final`；示例截图必须来自扩展实际运行。最终报告列出四个扩展点的具体调用位置、缺省行为和契约错误，包含至少三条 ADR、PlantUML 架构对比及由脚本产生的指标。最后检查 Git 提交、远端、工作区及 `p2` tag 指向。
